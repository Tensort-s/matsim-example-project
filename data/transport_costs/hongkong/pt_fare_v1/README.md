# Hong Kong PT fare v1 canonical interfaces

This directory is generated by:

```text
scripts/hong_kong_single_city/costs/pt/
```

The canonical machine-readable entry points are:

- `canonical_pt_fare_interface_manifest.json`: release boundary, per-mode
  canonical layers, production-leg boundary, Bus strict/simulation separation,
  and integration approval status;
- `pt_fare_layer_registry.csv`: one registry row per mode with audit, strict
  rule, simulation-candidate, quote-interface, semantic, unresolved-policy,
  quality, approval, and SHA256 fields;
- `pt_fare_release_validation.json`: release counts, registry hash checks,
  protected-input verification, and code/schema checks.

Mode-specific canonical layers are:

- `mtr_station_od_v1/`: adult Octopus station-OD rules; domestic MTR and
  Airport Express are separate fare-network scopes;
- `light_rail_station_od_v1/`: adult Octopus Light Rail station-OD base fares;
- `gmb_fare_v1/`: published GTFS amounts whose passenger/payment basis is
  unspecified; conflicts and identical duplicates remain unresolved;
- `ferry_fare_v1/`: published GTFS amounts whose passenger, payment, class,
  vessel, day, and effective-period applicability is unspecified;
- `bus_fare_v1/`: strict Bus Core unique published-amount rules;
- `bus_fare_simulation_v1/`: coverage-first Bus simulation candidates with
  B/C/D quality, assumption provenance, and anomaly fields. These candidates
  are not all unique official fares and never overwrite Bus Core.

The older top-level products remain source normalization and audit baselines:

- `official_fares_normalized.parquet`: historical normalized source catalog
  used for cross-checks, not a cross-mode quote interface and not governed by
  one global passenger/payment basis;
- `route_to_official_fare_match.csv`: historical official-to-MATSim
  route/station match;
- `transit_schedule_inventory.csv`: operator, line, route, mode, stop, and
  departure inventory;
- `pt_passenger_trip_fare_audit.parquet`: one chargeability audit row for
  every production PT passenger main leg; current generic PT legs have
  `cost_hkd=null` and `cost_quality=U`;
- `fare_source_manifest.csv` and `SHA256SUMS.txt`: provenance and integrity;
- `pt_fare_independent_validation.json`: independent row, schema, mapping,
  provenance, portability, parsed TD date, and protected-input validation.

The cross-mode distance median introduced in commit `c7be4a` is withdrawn and
its active estimate files are removed. The 557,104 generic production PT legs
remain unpriced because they lack actual mode, line, route, boarding,
alighting, and transfer-chain fields. Distance medians, cross-mode
aggregation, nearest-neighbour matching, and route `fullFare` substitution are
not permitted replacements. A future integration requires a runtime or
post-routing explicit PT itinerary.

Transfer concessions remain unmodelled. MATSim scoring and joint mode-choice
calibration are not approved. See `docs/HONG_KONG_PT_FARE_MODEL.md` for the
full source, matching, query, and limitation record.
